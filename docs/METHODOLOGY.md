# Методика mvp-1.0

Рабочая методика выбрана для реализации базового MVP. Это прозрачные начальные правила, которым нужна дальнейшая калибровка на реальных проектах; исходное обсуждение не утверждало эти веса.

## Формула

Каждый измеренный показатель получает значение от 0 до 100. Итог — взвешенное среднее **только известных** показателей:

```text
Health = sum(metric_score × metric_weight) / sum(known_metric_weight)
Coverage = sum(known_metric_weight)
```

Сумма всех предусмотренных весов — 100. Вход включает явный `collected_at`: расчёт не обращается к текущему системному времени. Баллы округляются до одного знака после запятой. Рекомендации не обещают конкретную прибавку.

| Показатель | Вес | Правило |
| --- | ---: | --- |
| README | 15 | Файл найден — 100, подтверждённо не найден — 0 |
| LICENSE / LICENCE / COPYING | 10 | Файл найден — 100, подтверждённо не найден — 0 |
| CONTRIBUTING | 5 | Файл найден — 100, подтверждённо не найден — 0 |
| Надёжность CI | 30 | 100 × число success / число success + failed + timeout за последние 30 дней, включая границу периода |
| Очередь issues | 20 | 100 × (1 − доля незавершённых issues без обновлений более 30 дней) |
| Запросы на слияние | 10 | 100 × (1 − доля open/merging без обновлений более 14 дней) |
| AppSec | 10 | Не подключён, неизвестно, вес исключается |

Документы ищутся без учёта регистра в корне, `docs`, `.sourcecraft`, `.github`. Расширения: отсутствует, `.md`, `.markdown`, `.rst`, `.txt`. Ссылки и вложенные каталоги глубже одного уровня не обходятся. Проверяется наличие файла, а не содержание или юридическая применимость лицензии.

Для issues используются `status_type`: `initial`, `in_progress`, `paused` — незавершённые; `completed`, `cancelled` исключены. Для запросов на слияние учитываются `open`, `merging`; `draft`, `discarded`, `merged` исключены. При отсутствии незавершённых задач показатель очереди равен 100: это отсутствие просроченного списка, а не доказательство активного сопровождения.

CI отменённый, пропущенный, отклонённый, ожидающий и выполняющийся не входит в знаменатель. Если подходящих завершённых запусков за период нет, показатель неизвестен. Сведения охватывают репозиторий целиком; отдельной фильтрации по веткам пока нет.

## Неизвестные сведения

Ошибка доступа, неполная пагинация и некорректные данные не дают ноль. Весь соответствующий показатель становится неизвестным. Устаревшая история CI без запусков за 30 дней тоже не даёт ноль. Если нет ни одного измеренного показателя или репозиторий пуст, итог — `null`, в интерфейсе «Недостаточно данных».

Полнота данных показывает долю измеренных весов, а не статистическую вероятность корректности. Максимальная полнота текущей версии — 90%, поскольку AppSec всегда неизвестен.

Пример: только все документы (30) и CI с успешностью 60% (30) известны. Итог `(100×30 + 60×30)/60 = 80`; полнота `60%`. Неизвестная безопасность не считается успешной проверкой.

## Рейтинг

В рейтинг допускаются непустые репозитории с итоговым числом, полнотой не ниже 60%, текущей версией методики и возрастом анализа не более 7 дней. Свежесть проверяется при чтении. Сортировка: оценка по убыванию, полнота по убыванию, каноническое имя по алфавиту.

Демо и реальные результаты выводятся отдельно. Рейтинг относится к добавленным в этот экземпляр сервиса репозиториям. Каталог возвращает не более 1000 последних проектов; обход всего SourceCraft в MVP отсутствует.

## Ограничения интерпретации

- Показатель не заменяет аудит безопасности и код-ревью.
- Качество документации, тестовое покрытие, git-история, релизы и концентрация вклада не оцениваются.
- Лайки не влияют на результат.
- Стабильные проекты не штрафуются за редкие коммиты.
- Полезность весов различается для библиотек, приложений, учебных проектов и форков. Специализированных профилей пока нет.
- Формальное обновление задач способно улучшить метрику без реального устранения проблемы. Устойчивость к такой накрутке — направление следующей версии.
- Старый отчёт отражает прошлое наблюдение. Статус внешних источников до повторного анализа неизвестен.

При изменении правил обновите `scoring.Version`, этот документ, страницу методики и тестовые ожидания. Старые отчёты не должны автоматически попадать в рейтинг новой версии.
