# Личный доступ SourceCraft в MVP

Дата: 18 сентября 2026 года.

## Как пользоваться

1. Запустить проект обычным запускателем и открыть сайт. Ввод токена в терминале больше не требуется.
2. Нажать «Подключить токен», вставить PAT и выбрать «Проверить и подключить».
3. В разделе «Мои анализы» указать `организация/репозиторий`. Поддерживаются public, internal и private, если SourceCraft разрешает их читать этому токену. Владеть репозиторием не обязательно.
4. Для общего каталога выбрать «Публичный каталог». Общий рейтинг использует только общую базу; личный PAT не подставляется в публичный сбор.
5. «Отключить и удалить данные» отменяет личные задания и удаляет сессию. Замена PAT также создаёт новую пустую сессию. Публичные данные не удаляются.

## Что хранится и где

PAT находится в памяти SourceCraft-клиента на сервере. В профиле браузера — случайный идентификатор в HttpOnly cookie. Личные нормализованные факты, очередь и отчёты хранятся в отдельной SQLite `:memory:` на каждую сессию, без записи в общую базу. Доменный расчёт получает только факты, не токен.

Срок — один час с момента подключения, без продления. По истечении часа доступ блокируется сразу; очистка ресурсов выполняется не позднее следующего прохода минутного таймера, с ожиданием завершения отменённых запросов. Отключение и замена очищают ресурсы явно. После перезапуска сервера личные подключения и отчёты исчезают. Закрытие вкладки не является отключением; вкладки одного профиля разделяют cookie. Лимиты: 16 сессий, 20 репозиториев на сессию, 30 POST в минуту на процесс.

Перед личным анализом и чтением каталога, отчёта или задания сервер повторно запрашивает описание соответствующего репозитория. При ошибке прав или сети сохранённые данные не выдаются. Каталог целиком закрывается, если доступ к любому из его проектов не подтверждён. Проверка прав относится к моменту запроса; уже увиденные пользователем данные отозвать невозможно. Личные ссылки имеют префикс `#/personal/`, API — `/api/v1/personal/`; истёкший доступ не переключается на публичное API.

## Границы реализации

- Это временная PAT-сессия, не вход через Я ID и не постоянный личный кабинет.
- Новые личные отчёты проходят через `rhs-2.0-rc1`, но пока обычно имеют статус «Недостаточно данных». Сборщик может читать доступные токену закрытые issues, однако без подтверждённых ответов и роли сопровождающего они не превращаются в балл. Личные результаты не публикуются и не сравниваются в общем рейтинге.
- AppSec не подключён. PAT не создаёт сканирование, не добавляет подписку и не подтверждает права на результаты безопасности. Security остаётся неизвестным источником.
- Подключение проверяется чтением `/repos?page_size=1`. Недоступность этого метода не позволяет подключить PAT. Общая успешная проверка не гарантирует доступ ко всем репозиториям и источникам.
- Отсутствие токена не мешает демо и просмотру общего каталога. Для публичного сбора можно отдельно настроить серверный `SOURCECRAFT_TOKEN`; личный токен его не заменяет.
- Текущий запуск — локальный. Ввод PAT по HTTP допустим только на localhost; удалённому развёртыванию нужны настройка HTTPS, доверия к прокси и дальнейшее управление пользователями. Произвольные `X-Forwarded-Proto` не считаются доказательством HTTPS.
- Приложение не пишет PAT на диск; настройка swap и защиты памяти — свойство хоста, а не гарантия приложения.

## Выполненные проверки

- `go test ./...`: все пакеты проходят.
- `go vet ./...`: замечаний нет.
- Синтаксис `web/app.js` и `web/access.js` проверен Node.js; новая версия собрана.
- HTTP-тесты: два независимых владельца, одинаковый репозиторий, чужие ID отчёта и задания, отсутствие личных данных в общем API и рейтинге, отзыв прав, замена токена, отключение, истечение сессии и освобождение worker.
- Защита запросов: неверный PAT, пустой и слишком длинный ввод, перенос строки, лишние JSON-поля, чужой Origin, неверный Content-Type, удалённый HTTP, Secure cookie для TLS.
- Контракт коллектора на тестовом HTTP-сервере: Bearer, проверка PAT, запрет приватного репозитория публичному коллектору, личный сбор закрытых issues, повторная проверка прав после отзыва. AppSec остаётся `not_connected`.
- Браузер Edge/Playwright: реальная встроенная страница, desktop 1440×1000 и mobile 390×844; ввод и очистка пароля, подключение, запуск личного анализа, обновление личной ссылки, переключение к публичному каталогу, отключение, отсутствие PAT в web storage и ошибок JavaScript. Скриншоты просмотрены, горизонтального переполнения нет.

Для браузерного успешного подключения ответы сессии и личного API были подставлены тестовыми данными. Реальный PAT пользователь не предоставлял: живой успешный доступ к приватному репозиторию и AppSec **не подтверждён**. Тесты выполнялись отдельно от пользовательской базы.
