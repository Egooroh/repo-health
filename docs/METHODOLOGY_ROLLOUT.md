# Подключение rhs-2.0-rc1: статус и границы

Дата: 18 сентября 2026 года.

Новые **реальные** публичные и личные отчёты передаются через `internal/scoring/current.go` в эталонный расчёт `internal/methodology.Evaluate`. Демо и уже сохранённые отчёты `mvp-1.0` остаются различимыми по версии. Старые реальные отчёты больше не входят в рейтинг; для пересчёта нужно нажать «Обновить оценку». Схема базы не менялась, пользовательская база не использовалась для тестов.

Пока расчёт не получает достаточно подтверждённых входов для численного балла. Это ожидаемый результат перехода, а не ошибка сети. Прежние 100 баллов за отсутствие открытых issues/PR больше не появляются: пустой список означает недостаточную выборку. Кандидат требует общую полноту не менее 60% и минимум три категории с покрытием не менее 60% каждая. Рейтинг требует полный, актуальный публичный отчёт. Личный отчёт исключён из рейтинга независимо от численного результата.

| Категория | Что уже получает MVP | Чего не хватает для rhs-2.0-rc1 | Вывод сейчас |
| --- | --- | --- | --- |
| Документация | Имена файлов из корня и нескольких каталогов | Чтение содержимого на фиксированной ревизии, проверяемые фрагменты для 10 пунктов, подтверждение полноты обхода | `incomplete` при доступном списке |
| CI | Статусы и время завершения запусков; хеш HEAD основной ветки собирается отдельно | Привязка каждого запуска к ветке, ревизии, pipeline ID, первая попытка, разные ревизии и достаточная выборка | `incomplete` при доступной истории |
| Состояние кода | Нет исходного кода в нормализованных фактах | Ограниченное чтение кода, закреплённые анализаторы сложности и дубликатов, тесты на языках | `missing` |
| Активность | Список PR | История содержательных изменений основной ветки и подтверждённые ответы сопровождающих на PR | `incomplete` или `insufficient` |
| Работа с задачами | Список issues и дата `updated_at` | Семисуточные ответы с автором и ролью, содержательное действие вместо косметического обновления, статус «ожидает автора» | `incomplete` или `insufficient` |
| Security | Нет подключения AppSec | Разрешённые реальные результаты SAST/SCA/secrets, состав проверок, ревизия, возраст, статусы находок | Только личный профиль; `missing` |

Формат README и имена файлов не подтверждают десять пунктов Documentation. Дата обновления issue не подтверждает ответа человека. У `/cicd/runs` в проверенной спецификации нет явных полей ревизии и pipeline в основной записи запуска. Подменять эти сведения предположением нельзя. [SourceCraft API](https://api.sourcecraft.tech/sourcecraft.swagger.json), [описание чтения raw-файла](https://vibe.sourcecraft.dev/portal/docs/en/sourcecraft/operations/raw-content), [скачивание публичного архива](https://vibe.sourcecraft.dev/portal/docs/en/sourcecraft/operations/repo-download-archive).

Порядок оставшихся работ:

1. Ревизия основной ветки уже фиксируется через `/branches` и проверяется по полному хешу; теперь проверить безопасный ограниченный доступ к её содержимому. Публичные raw-файлы поддерживаются документацией; доступ к приватному содержимому требует отдельной проверки на разрешённом репозитории и не должен подставлять PAT в URL или логи.
2. Реализовать документированные доказательства для 10 пунктов Documentation; автоматические правила должны проходить контрольные тексты и не засчитывать один заголовок или имя файла.
3. Выбрать и проверить способ получить историю коммитов и запусков CI с требуемой привязкой к ветке, ревизии и pipeline. При отсутствии полного набора оставлять `incomplete`.
4. Добавить комментарии и проверку ролей для Issues/PR; только затем считать своевременность ответов и очередь. Пустая когорта должна оставаться `insufficient`.
5. Подключить воспроизводимый анализ Code без запуска чужого кода и с ограничениями для больших репозиториев. Затем проверить AppSec по доступному аккаунту, актуальности и правам.
6. Откалибровать пороги на разнообразных реальных репозиториях, обновить версию после изменения правил, проверить пограничные случаи и доступ к личным данным.

Проверки интеграции: `go test ./...`, `go vet ./...`, `node --check web/app.js`, `node --check web/access.js`, `go run ./cmd/methodology-check`. Тест нового пути задания использует отдельную временную SQLite и пример со списками issues и PR без элементов: отчёт сохранён с `score:null`, `status:insufficient`, `coverage:0`, в рейтинге его нет. Эти проверки не подтверждают доступ к приватному SourceCraft или AppSec; реальный токен в тестах не использовался.
