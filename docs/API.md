# HTTP API MVP

Базовый адрес: `http://127.0.0.1:8080`. Все ответы API — JSON. Для POST требуется `Content-Type: application/json`, один JSON-объект и тело до 4096 байт. Неизвестные поля отклоняются.

| Метод и путь | Назначение |
| --- | --- |
| `GET /healthz` | Процесс отвечает: `{"status":"ok"}`; это проверка живости, не доступности SourceCraft |
| `GET /api/v1/meta` | Версия методики, наличие серверного токена, состояние подключения AppSec |
| `POST /api/v1/analyses` | Запустить анализ или получить существующее активное задание |
| `GET /api/v1/jobs/{id}` | Состояние конкретного задания |
| `GET /api/v1/repositories?demo=false` | Каталог последних 1000 реальных проектов, включая ошибки и незавершённые анализы |
| `GET /api/v1/repositories/{id}` | Последний отчёт и последнее задание репозитория |
| `GET /api/v1/leaderboard?demo=false` | Отсортированные проекты, отвечающие правилам рейтинга |
| `POST /api/v1/demo` | Создать три демонстрационных анализа; тело `{}` |

`demo=true` в запросах списка выбирает отдельный демонстрационный каталог. Тело анализа:

```json
{"ref":"examples/self-hosted-worker","demo":false}
```

Вместо `ref` в формате `организация/репозиторий` можно передать корневой HTTPS-адрес SourceCraft. Прочие хосты, порты, реквизиты в адресе, параметры, фрагменты и пути к разделам отклоняются.

Ответ `202 Accepted` содержит задание с полями `id`, `repository_id`, `ref`, `demo`, `status`, `created_at`. Заголовок `Location` указывает на `/api/v1/jobs/{id}`. Состояния: `queued → running → completed` либо `failed`; в ошибке есть безопасное поле `error`. Время — UTC в RFC3339.

У проекта поля `id`, `ref`, `demo`, `report`, `job`. Отчёт может быть `null`. Отчёт содержит описание репозитория, время, версию методики, `score` (число или `null`), `coverage`, `eligible`, объяснение допуска в рейтинг, категории, метрики, рекомендации и состояния источников. Даже при неудачном повторном анализе может сохраняться предыдущий отчёт; клиент обязан показывать статус последнего задания рядом с ним.

Списки имеют форму `{"items":[...],"count":N}`. Поле `count` — число возвращённых элементов.

Ошибка HTTP имеет форму `{"error":"Понятное сообщение"}`. Коды: 400 — неверный ввод, 403 — недопустимый Origin, 404 — объект не найден, 415 — неверный Content-Type, 429 — пауза/лимит очереди/частоты, 500 — внутренняя ошибка. Ошибка SourceCraft после постановки задания отражается в `job.status=failed`, а не изменяет уже возвращённый HTTP 202.

Токен SourceCraft не передаётся браузером и не возвращается в API. Отдельные пользовательские аккаунты и API-ключи самого Repo Health в MVP не реализованы. Для публикации сервиса требуется отдельное решение о доступе к POST-операциям.

## Временная личная сессия

| Метод | Путь | Поведение |
| --- | --- | --- |
| GET | `/api/v1/session` | `connected`, `expires_at` для активной сессии, `appsec_connected:false`; токен не возвращается |
| POST | `/api/v1/session` | JSON `{"token":"<PAT>"}`; проверяет чтение `/repos?page_size=1`, создаёт изолированную сессию и HttpOnly cookie, удаляет прежнюю сессию только после успешной проверки |
| POST | `/api/v1/session/disconnect` | JSON `{}`; отменяет задания, удаляет токен и личные результаты, сбрасывает cookie |
| POST | `/api/v1/personal/analyses` | JSON `{"ref":"org/repo"}`; проверяет права, ставит личный анализ в очередь; 202 и личный Location |
| GET | `/api/v1/personal/repositories` | Личные результаты с повторной проверкой доступа к каждому репозиторию |
| GET | `/api/v1/personal/repositories/{id}` | Только результат этой сессии, `report.eligible:false` |
| GET | `/api/v1/personal/jobs/{id}` | Только задание этой сессии с проверкой доступа к репозиторию |

Без действующей cookie личное API возвращает 401 и не переключается на публичное. Чужой ID — 404. Неподтверждённый доступ к известному личному репозиторию — 403 без выдачи сохранённых данных. Неверный или непроверенный PAT при подключении — 422, переполнение числа сессий — 503, числа репозиториев — 409. Личного рейтинга и демо API нет. Публичное API игнорирует личную cookie. `/meta.token_configured` по-прежнему относится только к серверному токену; статус браузерного подключения берётся из `/session`.

Тело до 4096 байт, PAT до 2048 ASCII символов без пробелов. POST требует JSON, того же Origin (если заголовок присутствует) и не допускает cross-site. Ввод токена по удалённому HTTP отклоняется. Сессия на один час; новый токен создаёт новый набор личных результатов.

## Версии отчётов после подключения rhs-2.0-rc1

`GET /api/v1/meta` возвращает `version: "rhs-2.0-rc1"`. Новые реальные отчёты имеют эту `version` и `status` (`insufficient`, `partial` или `complete`); при недостаточных фактах `score: null`, `coverage: 0` и `eligible: false`. Каждая категория содержит причину отсутствия проверенного измерения. Исторические записи `mvp-1.0` сохраняются без миграции и исключаются из нового рейтинга. Демо остаётся отдельным и использует историческую методику.

Снимок `repository.revision` содержит хеш HEAD основной ветки, если запрос SourceCraft `/branches` завершился полной проверкой; иначе поле отсутствует, а `sources.revision` объясняет причину. Само наличие хеша не даёт баллов за документацию, CI или код.
